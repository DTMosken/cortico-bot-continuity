# 接续 Continuity

接续 Continuity（npm 包名 `cortico-bot-continuity`）是 [Cortico](https://github.com/Pal-AI-Lab/Cortico) 的 Bot 扩展，适合长期运行的陪伴型、人格型机器人。它让机器人记住经历，在重启和长对话之后延续与每个人、每个群的相处方式，并按场景调整回应的主动程度。

## 功能

装好即可使用：

- **长期记忆**：经历、人物和备忘保存在 Memory 文件工作区中，由 Git 记录历史，可在控制台查看和回滚。
- **梦**：对话上下文写满后，机器人在后台整理这段经历，更新人物档案和长期约束，再带着交接笔记继续对话。
- **作息与闹钟**：没有消息时按白天、深夜不同的间隔醒来；机器人可以自己定闹钟，按时间或关键词醒来。
- **互动状态**：私聊按人、群聊按群记录关系亲近程度和群活跃度，随消息增加，随时间衰减。
- **认知帧**：每批消息到达时，提示机器人在当前场景适合多主动、多热情、多克制地回应。是否回复仍由机器人决定。
- **参与降温**：机器人连续发言后，参与意愿暂时降低，几小时后恢复，避免刷屏。
- **后台子代理**：机器人可以把耗时任务交给后台执行，自己继续聊天，完成后读取结果。

需要配置决策模型：

- **即时评估**：用决策模型读当前消息和近期对话，给出认知帧的各项建议。未配置时，认知帧使用随机值和互动状态计算。
- **强化 STATE 约束**：STATE 是梦维护的、适用于所有对话对象的长期约束。开启后，机器人发言或写入前由决策模型检查是否违反约束，有疑问时先暂缓，由机器人确认取消或坚持。

## 安装

本扩展只能在 Cortico 中安装。Coopanion 官方不支持安装 bot 类扩展。

要求 Cortico 0.2.13 或更新版本。

1. 在 Cortico 侧边栏打开“Bot 模板”，找到 cortico-bot-continuity，点击下载。
2. 新建 bot 时选择 cortico-bot-continuity。

基础功能装好即可使用。QQ、控制台聊天和网页搜索默认启用，各自的账号和参数在对应 World 的设置中填写。

### 配置决策模型

即时评估和强化 STATE 约束需要决策模型。在设置的 Continuity Persona → 认知帧 中选择“即时评估方式”：

| 方式 | 说明 | 需要准备 |
| --- | --- | --- |
| 随机（默认） | 不使用模型，按随机值和互动状态计算。不能开启强化 STATE 约束。 | 无 |
| 本地 Laya 英文版 | 在本机运行，首次使用时自动下载模型。只适合英文对话。 | 无 |
| 本地 Laya 多语言版 | 在本机运行，支持中文。 | 一个 Conda Python 环境，见下文。 |
| 远程决策模型（推荐） | 通过网络调用决策服务。 | 服务的 API key，并勾选“允许远程模型处理文本”。 |

建议使用远程决策模型。本地的小决策模型，如 Laya 和 4B 版 Decider，实测效果不及预期；大决策模型对硬件要求高；而决策模型 API 的调用费用很低。

远程决策模型可选的服务和模型：

| 决策服务 | 模型 | 密钥变量 |
| --- | --- | --- |
| TypeSafe | JEV | `CORTICO_JEV_TYPESAFE_API_KEY` |
| OpenRouter | JEV、Luna Decisions（`openai/gpt-6-luna-decisions`）、Decider（`~perplexity/pplx-decider-latest`） | `CORTICO_JEV_OPENROUTER_API_KEY` |
| 自定义 | 任何支持 SystemOne 接口的服务 | `CORTICO_JEV_API_KEY` |

模型输入框提供预设，也可以直接填写模型 ID。点击“打开密钥文件”填写密钥，再点击“保存并测试”确认连接。发给远程模型的消息文本中，链接、邮箱、密钥和 4 位以上的数字会被替换。

多语言 Laya 需要先在扩展目录运行一次安装命令，它会向指定的 Conda 环境安装 `laya` 并下载模型：

```powershell
corepack pnpm laya:multilingual:setup <Conda 环境名>
```

`conda` 不在 PATH 中时，先指定 Conda 可执行文件：

```powershell
$env:CORTICO_CONDA_COMMAND = '<Conda 安装目录>\Scripts\conda.exe'; corepack pnpm laya:multilingual:setup <Conda 环境名>
```

完成后，在认知帧页的“多语言 Laya Python 环境”中选择这个环境。

## 调参

以下参数都在设置的 Continuity Persona 中修改，保存后生效。这里只列出会明显改变机器人行为的参数。

### 认知帧

| 参数 | 默认值 | 效果 |
| --- | --- | --- |
| 参与度衰减 | 0.95 | 范围 0.8–1。机器人每成功发言一次，参与意愿乘以这个系数。调低后机器人发言几次就明显变安静，调到 1 关闭降温。降温在最后一次发言 3 小时后完全恢复。 |
| STATE 重复提醒间隔 | 10 批 | 每隔多少批消息重新提醒一次 STATE。调低让机器人更常想起长期约束，但占用更多上下文。0 关闭重复提醒。 |
| 白名单 / 黑名单 | 空 | 决定哪些消息生成认知帧，可按 World、事件类型、场景、发送者筛选，支持正则。被屏蔽的消息仍会送给机器人，只是不附认知帧。 |
| 强化 STATE 约束 | 关 | 见[功能](#功能)。需要先配置非随机的决策模型。 |
| 记录即时评估输出 | 关 | 在运行日志中记录每次评估的 8 项评分，用于观察和调试。不记录消息原文。 |

### 配置

| 参数 | 默认值 | 效果 |
| --- | --- | --- |
| 上下文阶段预算 | 128000 tok | 上下文达到这个大小时交接并入梦。调高让机器人在一段对话里记得更久，但每次请求更贵；调低让梦更频繁。 |
| 交接保留比例 | 0.1 | 交接笔记占阶段预算的比例。调高让交接后保留更多最近的对话原文。 |
| 工具循环软上限 / 硬上限 | 8 / 16 轮 | 机器人一次醒来最多连续行动多少轮。到软上限时提醒收尾，到硬上限直接结束。 |
| memo 常驻条数 / active 条数 | 7 / 21 | 备忘的容量。常驻备忘全文常驻在机器人眼前，active 只显示文件名。调高让机器人随时记得更多事，但占用更多上下文。 |
| 白天 tick 间隔 | 30–60 分钟 | 没有消息时，白天每隔多久醒来一次，在区间内随机。调低让机器人更常主动说话。 |
| 深夜 tick 间隔 | 120 分钟 | 深夜醒来的间隔，0 表示深夜不醒。 |
| 深夜起始 / 结束 | 0 点 / 8 点 | 深夜时段。 |

### 梦

| 参数 | 默认值 | 效果 |
| --- | --- | --- |
| 梦收尾提示轮次 / 轮数上限 | 40 / 60 轮 | 一场梦最多行动多少轮。调高让整理更充分，但更贵。 |
| 每次最多整理批数 | 3 批 | 积压材料较多时，一次入梦连续整理几批。1 表示每次只整理一批。 |
| 中断后最多重试次数 | 2 次 | 梦没有正常收尾时自动重试的次数。0 关闭重试。 |
| 已完成原始材料保留时间 | 30 天 | 已整理的对话原文保留多久，之后删除。Memory 中的整理结果不受影响。 |

### 子代理

| 参数 | 默认值 | 效果 |
| --- | --- | --- |
| 启用子代理 | 开 | 关闭后机器人不能委派后台任务，World 也不能请求后台计算。 |
| 模型端点 | 跟随主线 | 子代理使用的模型。可以选一个更便宜的端点。 |
| 同时运行上限 | 4 项 | 超出时新任务被拒绝，不排队。 |
| 轮数提醒起点 / 硬结束轮次 | 16 / 64 轮 | 单个任务最多行动多少轮。 |
| 任务时限 | 15 分钟 | 单个任务的最长运行时间。 |

子代理页还可以设置子代理能使用哪些工具。Memory 对子代理始终只读。

## 升级须知

- **0.8.0** 起需要 Cortico 0.2.13 或更新版本。
- **自定义提示词**：部署目录 `prompts/` 中的同名文件会覆盖包内的默认提示词，控制台中修改的提示词也保存在这里。升级到 0.8.0 时，如有以下覆盖文件，需要手动修改：
  - `PREFIX.md`：删除 `{{persona.subagents}}` 前面的 Subagents 段标题。
  - `SUBAGENTS.md`：在开头加上一行 `━━━ Subagents ━━━`。
  - `CORE.md`：对照新版 [CORE.md](persona/CORE.md)，合并 `mem:` 句柄的写法、写权限表中 `state/` 一行和 `qq_confirm` 的说明。

  没有特意修改过的覆盖文件可以直接删除，删除后使用包内的新版默认内容。
- **STATE 约束迁移**：旧版 STATE 只有正文，没有约束区。开启强化 STATE 约束后，认知帧页会显示“迁移旧约束”。点击后，后台任务把旧正文中可检查的要求整理成约束，在下次入梦时替换 STATE。
- **从 v1 首次启动**时，旧的运行状态和 STATE 分别归档为 `memory/state/runtime.v1.json` 和 `memory/state/STATE.v1.md`。

其他变更见 [CHANGELOG.md](CHANGELOG.md)。
